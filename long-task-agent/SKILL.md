# Long-Task Agent

Execute multi-session software projects by decomposing requirements into verifiable features, maintaining persistent state across sessions, and implementing one feature per context cycle with automatic `/clear` between cycles.

## Workflow Overview

Two phases, connected by persistent artifacts on disk:

1. **Initializer** (first session) — Read docs, decompose into features, scaffold project
2. **Worker** (every subsequent cycle) — Orient, bootstrap, implement one feature, persist, `/clear`

Determine which phase:
- **No `feature-list.json` in project dir?** → Run Initializer
- **`feature-list.json` exists?** → Run Worker

## Phase 1: Initializer

Run once. Steps:

1. **Read requirement doc and design doc** provided by user
2. **Run `scripts/init_project.py`** to scaffold all persistent artifacts:
   ```
   python <skill-dir>/scripts/init_project.py <project-name> --path <project-dir>
   ```
   Creates: `long-task-guide.md`, `CLAUDE.md` (appended), `feature-list.json`, `task-progress.md`, `RELEASE_NOTES.md`, `init.sh`, `init.ps1`
3. **Copy `scripts/validate_features.py`** into `<project-dir>/scripts/`
4. **Decompose requirements into features** — Populate `feature-list.json`:
   - Each feature: `id`, `category`, `title`, `description`, `priority` (high/medium/low), `status` (always `"failing"` initially), `verification_steps` (concrete, specific), `dependencies` (feature id array)
   - Aim for 10-200+ features; each independently verifiable and completable in one session
   - Order by priority and dependency chain
5. **Validate**: `python scripts/validate_features.py feature-list.json`
6. **Customize `init.sh` / `init.ps1`** for the tech stack
7. **Scaffold project skeleton** (dirs, configs, dependency manifests)
8. **Git init + initial commit**
9. **Run init script**, verify environment works
10. **Update `task-progress.md`** with Session 0 entry
11. **Begin first Worker cycle** (proceed to Phase 2)

## Phase 2: Worker

Each Worker cycle follows the steps in `long-task-guide.md` (generated by init_project.py). The cycle:

1. **Orient** — read `task-progress.md`, `feature-list.json`, `git log`; pick next failing feature
2. **Bootstrap** — run `init.sh`/`init.ps1`; smoke-test passing features
3. **TDD Red** — write failing tests FIRST: unit tests for all features; Chrome DevTools MCP functional tests for UI features
4. **TDD Green** — implement minimal code to make all tests pass
5. **TDD Refactor** — refactor while keeping tests green; run full verification
6. **Verify & Mark** — run `verification_steps` from feature-list.json; mark `"passing"` ONLY after ALL tests (UT + functional) pass
7. **Persist** — git commit; update `task-progress.md`; update `RELEASE_NOTES.md`; validate feature list; commit again
8. **Clear & continue** — if failing features remain, execute `/clear` then send: `"Continue working on this project. Read long-task-guide.md for instructions."`

### Context Continuity Mechanism

After `/clear`, Claude Code auto-reads the project's `CLAUDE.md`, which contains:
```
Read `long-task-guide.md` at the start of EVERY session and follow its instructions.
```
This ensures the agent immediately reads the full worker guide and picks up the next task — no manual prompt needed beyond the trigger message.

For detailed architecture, artifact formats, and anti-patterns, see [references/architecture.md](references/architecture.md).

## Critical Rules

- **Never remove or edit `verification_steps`** — immutable once created
- **Never mark `"passing"` without verification** — run actual tests (UT + functional)
- **Strict TDD** — always write failing tests before implementation code; never skip Red→Green→Refactor
- **UI features require Chrome DevTools MCP testing** — use `take_snapshot`, `click`, `fill`, `take_screenshot` etc. to verify UI behavior functionally
- **Update `RELEASE_NOTES.md` after every git commit** — keep it in sync with project progress
- **JSON for feature list** — models corrupt markdown more easily
- **One feature per cycle** — prevents context exhaustion
- **Always commit + update progress + update release notes before `/clear`** — bridges context gap
- **Never leave broken code** — revert incomplete work
